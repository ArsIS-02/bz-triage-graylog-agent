# Архитектура

## Задача

Собирать телеметрию macOS (autoruns, процессы, сеть, пользователи,
подписи, хеши) с парка машин и централизованно анализировать её в Graylog —
без разработки и поддержки собственного EDR-агента.

## Решение

Использовать `bz_triage` (BI.ZONE Triage) как готовый коллектор и
Graylog как центральный анализатор.

```text
┌──────────────┐   JSON Lines    ┌───────────────┐
│  bz_triage   │ ──────────────> │   Graylog     │
│  на хосте    │  TCP :5555      │  Raw TCP +    │
└──────────────┘                 │ JSON Extractor│
       │                         └───────────────┘
       │ --outdir=/tmp/bzt.XXXX
       ▼
   временные файлы
   (trap cleanup → rm -rf)
```

## Почему именно так

### Почему `bz_triage`, а не свой агент

- `bz_triage` — подписанный бинарь от вендора, не нужно писать и
  поддерживать свой сборщик.
- Уже умеет то, что нам нужно: autoruns, процессы, сеть, пользователей,
  подписи, хеши.
- Кроссплатформенный (macOS / Linux / Windows) — одна логика на всех хостах.
- Регулярно обновляется вендором.

### Почему `--dsthost` / `--dstport`, а не Filebeat / Logstash / Vector

- У `bz_triage` уже есть встроенная отправка по сети — не нужно
  ставить и конфигурировать промежуточный шиппер.
- Никаких JVM/Python-прослоек на хосте: меньше поверхности атаки, меньше
  зависимостей, меньше обслуживания.
- Меньше движущихся частей — легче диагностировать.

### Почему Graylog, а не Elasticsearch / Splunk

- Graylog бесплатен, ставится быстро, есть встроенные Streams, Pipelines,
  алерты.
- Raw TCP Input + JSON Extractor закрывают потребность в парсинге
  «сырого» JSON от `bz_triage` без написания кода.

## Компоненты

| Компонент | Роль | Где живёт |
|-----------|------|-----------|
| `bz_triage` | Сбор телеметрии, отправка JSON | На каждом хосте |
| `bzt-stream.sh` | Обёртка: outdir + trap + watchdog | На каждом хосте |
| `launchd` | Периодический запуск обёртки | На каждом хосте |
| Graylog | Приём, парсинг, хранение, анализ | Центрально |

## Поток данных

1. `launchd` запускает `bzt-stream.sh` по расписанию.
2. Скрипт создаёт `mktemp -d /tmp/bzt.XXXXXX`.
3. `bz_triage` собирает данные в `outdir` и параллельно шлёт JSON-строки
   на `--dsthost:--dstport`.
4. Graylog принимает поток через Raw TCP Input.
5. JSON Extractor раскладывает поля.
6. Streams / Pipelines / алерты работают поверх структурированных полей.
7. После завершения `bz_triage` скрипт удаляет `outdir` через `trap`.

## Ограничения

- `bz_triage` — не демон. «Непрерывность» достигается периодическим
  запуском по расписанию.
- Нет фильтрации на стороне хоста: если поле не нужно, его надо
  удалять в Graylog Pipeline.
- `--dsthost` не отключает локальное сохранение — `outdir` нужно
  чистить самому (в нашем скрипте это делает `trap`).
