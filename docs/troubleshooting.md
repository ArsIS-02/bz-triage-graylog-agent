# Известные грабли

## `outdir` не создаётся после `sudo -i`

**Симптом:** после блока команд вроде

```bash
sudo -i
mkdir -p /tmp/bzt_test
cd /tmp/bzt_test
/path/to/bz_triage -p=hostinfo --outdir=/tmp/bzt_test/out
```

каталога `out` нет, промпт остался в `~ root#`, а `cd` как будто не
сработал.

**Причина:** при пасте многострочного блока в `sudo -i` команды уходят
в буфер обычного shell (под которым был вызван sudo), а `sudo -i`
открывает новый root-shell с cwd в `/var/root`. Строки, которые должны
были выполниться, «разъезжаются» по двум шеллам.

**Решение:** выполнять команды по одной, уже находясь в root-shell.
Проверить, что мы там, где думаем:

```bash
pwd
whoami
```

## `bz_triage` не принимает `-p=hostinfo`

**Симптом:** команда завершается без вывода и без `outdir`.

**Причина:** синтаксис флагов зависит от версии. Возможно, нужно
`-p hostinfo`, `--profile=hostinfo` или иное.

**Решение:**

```bash
/Users/igor/bz_triage-v1.3.0.1-darwin-arm64 --help 2>&1 | head -60
```

Проверить точный синтаксис и наличие флагов `--dsthost`, `--dstport`,
`--dstproto`.

## `bz_triage` требует существующий `outdir`

**Симптом:** каталог, указанный в `--outdir`, не создаётся автоматически.

**Решение:** создать заранее:

```bash
OUTDIR=$(mktemp -d /tmp/bzt.XXXXXX)
```

В `bzt-stream.sh` это уже сделано.

## `file_exists: false` в autoruns

**Симптом:** много записей с `file_exists: false`, хотя `file_path`
указан.

**Причина:** на macOS beta часть путей в системных plist'ах устарела.
Это не баг сенсора.

**Решение:** не считать такие записи аномалией. При анализе фильтровать
`file_exists: true`, если нужны только реально существующие файлы.

## `file_content` раздувает индекс Graylog

**Симптом:** индекс `bz_triage` растёт слишком быстро.

**Причина:** `file_content` содержит первые байты бинарника и занимает
сотни байт на запись.

**Решение:** удалять поле в Pipeline Rule (см. `graylog-setup.md`, п.4).

## «Непрерывность» — это не демон

**Симптом:** ожидание, что `bz_triage` будет работать постоянно.

**Реальность:** `bz_triage` — одноразовый сборщик. «Непрерывность»
достигается периодическим запуском через `launchd` (StartInterval).

**Рекомендация:** интервал в 2–3 раза больше времени сбора. Если
`investigation` собирается за 30 секунд — интервал 15–30 минут.

## Прямая отправка через `--dsthost` не работает

**Диагностика:** запустить локальный listener и посмотреть, что придёт.

```bash
# Терминал 1
nc -l 5555 > /tmp/bzt_stream.log

# Терминал 2 (root)
/usr/local/bin/bz_triage \
    -p=hostinfo \
    --limit-time=60 \
    --outdir=/tmp/bzt_test \
    --dsthost=127.0.0.1 \
    --dstport=5555
```

Затем:

```bash
wc -l /tmp/bzt_stream.log
head -1 /tmp/bzt_stream.log | jq .
```

**Что проверить:**

- Если лог пустой, а `outdir` полон — сенсор требует другого флага
  (`--dstenable`?) или использует UDP (`nc -ul 5555`).
- Если данные идут с префиксом длины перед JSON — это не чистый JSON
  Lines, и в Graylog потребуется более хитрый Extractor.

## Пара «стандартных» для macOS beta

- `SystemOSName: "macOS 27.0 arm64 #27.0.0"` — фиксируйте в отчётах
  как «среда бенчмарка», поведение может отличаться от релизных macOS.
- `sensor_install_age: 1` — если сенсор запущен прямо под прогон,
  это поле всегда будет ~0 и не имеет смысла как метрика.
